# PR前セルフレビュー

## 手順

1. `git diff main...HEAD` で変更差分を確認する
2. `checklist.md` の観点で1つずつチェックする
3. テストとlintを実行し、結果をそのまま示す（実行コマンドはプロジェクトの package.json などに従う）
4. 指摘を「必須修正」「推奨」に分けて報告する
5. 認証・入力処理・外部通信・権限に関わる変更があれば、differential-review スキルでセキュリティ観点も確認する
6. 必須修正がなければ、下の型でPRの説明文の下書きを作る

## 注意

- 勝手にコードを修正しない。修正は指摘してから確認を取る
- `main` へ直接 push しない。PR は作業ブランチから作る

## PR説明文の型

```markdown
## 何を変えたか
（1〜3行）

## なぜ変えたか
（背景・関連Issue）

## 確認したこと
- [ ] テスト: （実行コマンドと結果）
- [ ] 画面での動作確認: （該当する場合）

## レビューしてほしい点
（不安な箇所があれば）
```
